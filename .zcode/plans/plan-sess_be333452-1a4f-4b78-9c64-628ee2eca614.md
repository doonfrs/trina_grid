# Column Filter Select Modes (Boolean dropdown + Multi-select checkboxes)

## Summary

Add two new column-filter modes alongside the existing text filter, activated **automatically by column type** (per your choice), with live filtering on every checkbox toggle:

- **Boolean columns** (`is_active`): dropdown with **ALL / True / False** replacing the text field. Selecting ALL clears the filter.
- **Select columns** (`hobby`): dropdown with **checkboxes** for each item (swimming, gym, …), a tristate "Select all" toggle, and live re-filtering on every check/uncheck. Empty selection = ALL = no filter.
- **Text columns** (`name`): unchanged text filter.
- Explicit delegate constructors let you force either mode on any column, or force plain text (`.textField()`) to opt out of auto-detection.

Filter values flow through the existing pipeline: `TrinaGridChangeColumnFilterEvent` → `setFilterWithFilterRows` → `FilterHelper.convertRowsToFilter` → `TrinaFilterType.compare`. Boolean uses `TrinaFilterTypeEquals` with `'true'`/`'false'` (cell values stringify to exactly these); multi-select reuses the existing `TrinaFilterTypeMultiItems` (splits value on `[\n,]`, exact membership) with items joined by newline. Empty value ⇒ `setFilterRows` drops the row ⇒ filter cleared. No new comparison semantics needed, and `filterOnlyEvent` (lazy pagination) keeps working.

## Changes by file

### 1. `lib/src/model/trina_column.dart` — delegate API
- Change `filterWidgetDelegate` default from `const TrinaFilterColumnWidgetDelegate.textField()` to `null` (null = auto-resolve; the only consumer reads it with `?.`, and `.textField()` becomes the explicit opt-out).
- Add to `TrinaFilterColumnWidgetDelegate`:
  - `const TrinaFilterColumnWidgetDelegate.booleanSelect()` — force the ALL/True/False dropdown.
  - `const TrinaFilterColumnWidgetDelegate.multiSelect({List<String>? items, bool caseSensitive = false})` — force checkbox mode; `items` null ⇒ derive from the column's select type (`items` mapped through `itemToValue ?? toString` so entries match actual cell values).
  - New fields `isBooleanSelect`, `isMultiSelect`, `multiSelectItems`; existing constructors initialize them to false/null.

### 2. `lib/src/model/trina_column_type.dart` — select-column gate
- Flip `enableColumnFilter` default `false → true` in the three select factories. The flag is currently declared but never read anywhere; it becomes the documented opt-out gate: `TrinaColumnType.select(..., enableColumnFilter: false)` keeps the plain text filter. Flipping the default is safe because nothing consumed it before.

### 3. New widget `lib/src/widgets/boolean_column_filter.dart` — `BooleanColumnFilter`
- Compact `MenuAnchor` field (current label + `Icons.arrow_drop_down`, filter-row styling: same fill/border colors as the TextField) that opens a `TrinaDropdownMenu<String>` with the three options and a checkmark on the current one (reuse gets scrolling/styling/keyboard for free).
- Selection → `onChanged('' | 'true' | 'false')`; disabled look when the filter is disabled (composite filter present).
- Unknown raw values (e.g. set via the F3 filter popup) display as-is; empty displays `ALL`.

### 4. New widget `lib/src/widgets/multi_select_column_filter.dart` — `MultiSelectColumnFilter`
- Compact `MenuAnchor` field: shows `ALL` hint when nothing selected, else comma-joined selection (ellipsized), with arrow + clear suffix icon.
- Custom menu content (TrinaDropdownMenu has no multi-select): header with tristate Checkbox + locale "Select all", divider, then a scrollable checkbox list (max height ~300, width = column width clamped to a minimum). Toggling does **not** close the menu; every toggle immediately fires `onChanged` with the selected items joined by `'\n'` (empty when none).
- Checkbox/selection state derives from the current filter value (split on `[\n,]`), so programmatic `setColumnFilter` and the filter popup stay in sync.

### 5. `lib/src/ui/columns/trina_column_filter.dart` — wiring
- Mode resolution (custom builder > legacy `multiItems` > explicit `booleanSelect` > explicit `multiSelect` > **auto**: boolean type → boolean mode, select type with `enableColumnFilter` → multi-select mode > text field).
- `_handleOnChanged` gains an optional `TrinaFilterType` parameter (Equals for boolean, MultiItems for multi-select); dispatched with `TrinaGridEventType.normal` (no debounce — selections are discrete).
- Keyboard: child widgets register an open-menu callback; Down/Enter/Space opens the dropdown instead of moving focus into rows; Tab/F3 navigation unchanged.

### 6. `lib/src/manager/event/trina_grid_change_column_filter_event.dart` — correctness fix
- `_getFilterRows` currently updates only the **value** cell of an existing filter row; also update the **type** cell. Otherwise a row previously created with `Contains` (filter popup / programmatic) would string-match `"swimming\ngym"` instead of using MultiItems semantics. Behavior-preserving for the text widget (it always passes `column.defaultFilter`).

### 7. `lib/src/trina_grid_configuration.dart` — locale
- Add to `TrinaGridLocaleText` (all ~15 constructor variants, English defaults): `filterAll` = 'ALL', `filterTrue` = 'True', `filterFalse` = 'False', `filterSelectAll` = 'Select all'.

## Behavior changes to note in CHANGELOG/docs
- Boolean columns' filter row becomes the ALL/True/False dropdown (opt out: `.textField()` delegate).
- Select columns' filter row becomes the checkbox multi-select (opt out: `enableColumnFilter: false` or `.textField()` delegate).
- `filterWidgetDelegate` now defaults to null (auto) — non-breaking, single null-safe consumer.
